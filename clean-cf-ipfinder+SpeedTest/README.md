# CloudflareSpeedTest (نسخه‌ی فینگلیش + منوی صفحه‌ی اول)

> پروژه‌ی اصلی: [XIU2/CloudflareSpeedTest](https://github.com/XIU2/CloudflareSpeedTest) — مجوز GPL-3.0

بسیاری از وب‌سایت‌ها از Cloudflare CDN استفاده می‌کنند، ولی IPای که به همه‌ی کاربران داده می‌شود همیشه بهترین نیست (تأخیر بالا، افت بسته، سرعت پایین). Cloudflare همه‌ی [رنج IPهایش](https://www.cloudflare.com/ips/) را عمومی کرده است، اما پیدا کردن بهترین IP بین این‌همه IP با دست کار سختی است. این برنامه **تأخیر و سرعت دانلود** IPها را (IPv4 و IPv6) تست می‌کند و **سریع‌ترین IP** را به شما می‌دهد.

برنامه روی **سایر CDNها و سایت‌های دارای چند IP** هم کار می‌کند؛ فقط آدرس تست دانلود را باید خودتان پیدا کنید.

> [!IMPORTANT]
> Cloudflare استفاده‌ی پروکسی‌گونه از CDN را صریحاً ممنوع کرده است. اگر از آن برای «پروکسی پشت CDN» استفاده می‌کنید، ریسکش با خودتان است و بیش از حد به آن وابسته نشوید.

> [!NOTE]
> این برنامه فقط برای **وب‌سایت‌ها** (TCP/HTTP) است و برای **Cloudflare WARP** که از UDP استفاده می‌کند کار نمی‌کند.

****

## \# این نسخه چه فرقی دارد؟

1. **فینگلیش:** همه‌ی کدها، کامنت‌ها، پیام‌های برنامه، سرستون‌های جدول/CSV و اسکریپت‌ها به **فینگلیش** (فارسی با حروف لاتین) ترجمه شده‌اند تا هیچ مشکل encoding در کنسول و فایل‌ها پیش نیاید. **فقط فایل‌های README فارسی هستند.**
2. **منوی صفحه‌ی اول:** اگر برنامه را بدون پارامتر اجرا کنید (مثلاً دابل‌کلیک)، قبل از شروع تست یک صفحه‌ی تنظیمات باز می‌شود که در آن **حالت تست و خروجی‌های موردنیاز** را انتخاب می‌کنید و بعد تست شروع می‌شود. دیگر لازم نیست پارامترهای خط فرمان را حفظ باشید.
3. **خروجی‌های بیشتر:** علاوه بر CSV، خروجی **TXT** (فقط IPها، هر خط یک IP) و خروجی **JSON** هم دارد.
4. **سازگاری با اسکریپت‌ها:** اگر پارامتر بدهید، یا ورودی از pipe بیاید، یا `-nomenu` بگذارید، منو نمایش داده **نمی‌شود** و برنامه مثل قبل کار می‌کند.

> [!NOTE]
> چون ستون‌های جدول و CSV فینگلیش شده‌اند، اسم سرستون‌ها با نسخه‌ی اصلی فرق دارد. ترتیب ستون‌ها (IP در ستون اول) تغییر نکرده است، پس اسکریپت‌های قدیمی که ستون اول را می‌خوانند بدون مشکل کار می‌کنند.

****

## \# شروع سریع

### ساخت (build) و اجرا

برنامه با زبان Go نوشته شده است (حداقل Go 1.18). در پوشه‌ی پروژه:

```bash
go build -ldflags "-s -w -X main.version=v1.0.0-finglish" -o cfst
```

(در ویندوز خروجی را `cfst.exe` بگذارید.) سپس:

- **ویندوز:** روی `cfst.exe` دابل‌کلیک کنید.
- **لینوکس / macOS:** در ترمینال `chmod +x cfst` و سپس `./cfst`

با این کار **منوی صفحه‌ی اول** باز می‌شود.

> اگر میانگین تأخیر **خیلی کم** باشد (مثلاً 0.xx)، یعنی تست از داخل پروکسی رد شده است؛ نرم‌افزار پروکسی/VPN را ببندید و دوباره تست کنید. روی **روتر** هم بهتر است پروکسی را خاموش کنید یا برنامه را از آن مستثنی کنید.

> بعد از روشن شدن کامپیوتر، اولین تست معمولاً تأخیر بالاتری نشان می‌دهد. پیشنهاد می‌شود قبل از تست اصلی یک تست کوتاه بگیرید.

## \# منوی صفحه‌ی اول

بعد از اجرا چنین صفحه‌ای می‌بینید (عدد جلوی هر گزینه را بزنید و Enter کنید):

```text
======================================================================
  CloudflareSpeedTest v1.0.0  -  nesakhe-ye Finglish
  Safhe-ye avval: halat-e test va khoroji-ha ra entekhab konid
======================================================================
  [1] Halat-e test (TCPing / HTTPing) : TCPing
  [2] Pish-tanzim (sari / daghigh)    : thread=200, tekrar=4, download=10 ta, modat=10 sanie
  [3] Manba-ye IP-ha                  : ip.txt
  [4] Test-e download                 : roshan (10 IP, har kodam 10 sanie)
  [5] Filter-ha (takhir, gom-shodan)  : tl=9999, tll=0, tlr=1.00, sl=0.00
  [6] Khoroji-ha (namayesh, CSV, ...) : namayesh=10 | CSV=result.csv | TXT=khamush | JSON=khamush
  [7] Tanzimat-e pishrafte            : port=443, thread=200, tekrar=4, debug=khamush
  [S] Shoro-e test
  [Q] Khorooj
```

مقدار فعلی هر بخش جلوی آن نوشته شده است. هر زیرمنو را باز کنید، مقدار را عوض کنید و دوباره به صفحه‌ی اصلی برمی‌گردید. در هر پرسش، **Enter = نگه داشتن مقدار فعلی**. وقتی آماده بودید **`S`** را بزنید تا خلاصه‌ی تنظیمات نشان داده شود و تست شروع شود. با **`Q`** از برنامه خارج می‌شوید.

### \[1\] حالت تست

| حالت | توضیح |
|------|-------|
| **TCPing** | سریع و کم‌مصرف (پیش‌فرض). کد منطقه (colo) را در مرحله‌ی تأخیر نشان نمی‌دهد. |
| **HTTPing** | دقیق‌تر؛ با درخواست HTTP تست می‌کند، کد منطقه را نشان می‌دهد و **فیلتر منطقه** (مثل `HKG,LAX`) دارد. آدرس تست، کد وضعیت معتبر HTTP و مناطق دلخواه را می‌پرسد. |

### \[2\] پیش‌تنظیم (سرعت / دقت)

| پیش‌تنظیم | thread | تکرار تأخیر | تعداد دانلود | مدت دانلود |
|-----------|:------:|:-----------:|:------------:|:----------:|
| سریع (Sari) | 300 | 2 | 5 | 5 ثانیه |
| متوسط (Motevaset) — پیش‌فرض | 200 | 4 | 10 | 10 ثانیه |
| دقیق (Daghigh) | 200 | 8 | 20 | 15 ثانیه |
| فقط تأخیر | 300 | 4 | — | بدون تست دانلود |

### \[3\] منبع IPها

`ip.txt` (IPv4)، `ipv6.txt` (IPv6)، یک فایل دلخواه، یا وارد کردن دستی IP/رنج‌ها (با ویرگول جدا شوند، مثل `1.1.1.1,2.2.2.2/24`). ورودی دستی قبل از شروع اعتبارسنجی می‌شود. همین‌جا می‌توانید **تست همه‌ی IPهای هر رنج** (`-allip`) را روشن کنید (کندتر است).

### \[4\] تست دانلود

روشن/خاموش کردن، آدرس تست، تعداد IPهایی که دانلود تست می‌شوند (`-dn`) و مدت دانلود هر IP (`-dt`). اگر خاموش باشد نتیجه بر اساس **تأخیر** مرتب می‌شود.

### \[5\] فیلترها

حد بالا/پایین میانگین تأخیر (`-tl` / `-tll`)، حد بالای افت بسته (`-tlr`) و حداقل سرعت دانلود (`-sl`).

### \[6\] خروجی‌ها

- **تعداد نتایج روی صفحه** (`-p`؛ صفر یعنی نمایش نده)
- **CSV** — نتیجه‌ی کامل (پیش‌فرض `result.csv`)
- **TXT** — فقط IPها، هر خط یک IP؛ می‌توانید فقط N تای اول را بنویسید (مناسب برای کپی در تنظیمات کلاینت‌ها و اسکریپت‌ها)
- **JSON** — همه‌ی اطلاعات به‌صورت ساخت‌یافته (برای برنامه‌نویسی)

هر خروجی را جداگانه روشن/خاموش و اسم فایلش را تعیین می‌کنید. اگر همه‌ی خروجی‌ها خاموش باشند، قبل از شروع به شما هشدار داده می‌شود.

### \[7\] تنظیمات پیشرفته

تعداد thread (`-n`)، تعداد تکرار تست تأخیر (`-t`)، پورت (`-tp`) و حالت اشکال‌یابی (`-debug`).

> [!TIP]
> اگر می‌خواهید منو را حتماً ببینید، `-menu` بگذارید (پارامترهای دیگری که همراهش بدهید مقدار اولیه‌ی منو می‌شوند). اگر نمی‌خواهید منو بیاید، `-nomenu` بگذارید.

## \# نمونه‌ی نتیجه

پس از تست، به‌صورت پیش‌فرض **۱۰ IP سریع‌تر** نمایش داده می‌شود:

```bash
Adres IP          Ersal shode  Daryaft shode  Gom-shodan  Miangin takhir  Sorat download(MB/s)  Kod mantaghe
104.27.200.69     4            4              0.00        146.23          28.64                 LAX
172.67.60.78      4            4              0.00        139.82          15.02                 SEA
104.25.140.153    4            4              0.00        146.49          14.90                 SJC
...
```

**ردیف اول** هم سرعت دانلود بالا و هم تأخیر کم دارد. نتیجه‌ی کامل در `result.csv` ذخیره می‌شود (با Notepad یا برنامه‌ی جدول باز کنید):

```text
Adres IP,Ersal shode,Daryaft shode,Gom-shodan,Miangin takhir,Sorat download(MB/s),Kod mantaghe
104.27.200.69,4,4,0.00,146.23,28.64,LAX
```

مراحل برنامه با پارامترهای پیش‌فرض:

1. تست تأخیر (پیش‌فرض TCPing)
2. مرتب‌سازی بر اساس تأخیر و فیلتر شرایط (افت بسته‌ی متفاوت جدا مرتب می‌شود)
3. تست دانلود (از کم‌تأخیرترین IP شروع می‌شود، پیش‌فرض تا ۱۰ IP)
4. مرتب‌سازی بر اساس سرعت
5. خروجی (صفحه / CSV / TXT / JSON)

> هر بار از هر رنج IP تصادفی انتخاب می‌شود، پس نتیجه‌ها هر بار فرق می‌کنند؛ این طبیعی است.

> [!NOTE]
> اگر سرعت دانلود **0.00** شد، با `-debug` علت را بررسی کنید (بخش «سرعت دانلود همه 0.00 است؟» پایین‌تر).

## \# پارامترهای خط فرمان

بدون پارامتر اجرا = پارامترهای پیش‌فرض (و در ترمینال، منوی صفحه‌ی اول). پارامترها ترتیب مشخصی ندارند.

```text
-n 200
    thread تست تأخیر؛ بیشتر = سریع‌تر؛ روی دستگاه ضعیف (مثل روتر) زیاد نکنید (پیش‌فرض 200، حداکثر 1000)
-t 4
    تعداد دفعات تست تأخیر برای هر IP (پیش‌فرض 4)
-dn 10
    تعداد IP برای تست دانلود، از کم‌تأخیرترین (پیش‌فرض 10)
-dt 10
    حداکثر زمان دانلود برای هر IP، نباید خیلی کوتاه باشد (پیش‌فرض 10 ثانیه)
-tp 443
    پورت تست تأخیر/دانلود (پیش‌فرض 443)
-url https://cf.xiu2.xyz/url
    آدرس تست تأخیر (HTTPing) و دانلود؛ پایداری آدرس پیش‌فرض تضمین نیست، بهتر است آدرس شخصی بسازید

-httping
    تست تأخیر با پروتکل HTTP به جای TCP (آدرس تست = -url)
-httping-code 200
    کد وضعیت HTTP معتبر در HTTPing، فقط یک کد (پیش‌فرض 200 و 301 و 302)
-cfcolo HKG,KHH,NRT,LAX,SEA,SJC,FRA,MAD
    فیلتر منطقه (کد IATA فرودگاه یا کد کشور/شهر)، با ویرگول انگلیسی؛ فقط در HTTPing (پیش‌فرض همه‌ی مناطق)

-tl 200
    حد بالای میانگین تأخیر (پیش‌فرض 9999 ms)
-tll 40
    حد پایین میانگین تأخیر (پیش‌فرض 0 ms)
-tlr 0.2
    حد بالای افت بسته، از 0.00 تا 1.00؛ صفر یعنی هر IP دارای افت حذف شود (پیش‌فرض 1.00)
-sl 5
    حداقل سرعت دانلود؛ تا پیدا شدن تعداد -dn تست ادامه می‌یابد (پیش‌فرض 0.00 MB/s)

-p 10
    تعداد نتایج نمایش‌داده‌شده؛ اگر 0 باشد چیزی نمایش داده نمی‌شود و برنامه خارج می‌شود (پیش‌فرض 10)
-f ip.txt
    فایل رنج‌های IP؛ اگر مسیر فاصله دارد داخل کوتیشن بگذارید (پیش‌فرض ip.txt)
-ip 1.1.1.1,2.2.2.2/24,2606:4700::/32
    رنج‌های IP مستقیماً با پارامتر، با ویرگول جدا شوند
-o result.csv
    فایل خروجی CSV؛ مقدار خالی یعنی ننویس (-o "")؛ (پیش‌فرض result.csv)
    نکته: در بعضی محیط‌ها (مثل PowerShell) پارامتر خالی نادیده گرفته می‌شود؛ از -o " " (با یک فاصله) استفاده کنید
-otxt result.txt
    [جدید] فایل خروجی TXT؛ فقط IPها، هر خط یکی (پیش‌فرض خاموش)
-txtn 5
    [جدید] تعداد IP در فایل TXT؛ 0 یعنی همه (پیش‌فرض 0)
-ojson result.json
    [جدید] فایل خروجی JSON (پیش‌فرض خاموش)

-dd
    غیرفعال کردن تست دانلود؛ نتیجه بر اساس تأخیر مرتب می‌شود
-allip
    تست همه‌ی IPهای هر رنج (فقط IPv4)؛ پیش‌فرض: در هر /24 یک IP تصادفی

-menu
    [جدید] حتماً منوی صفحه‌ی اول را نشان بده
-nomenu
    [جدید] منو را نشان نده (برای اسکریپت‌ها)
-debug
    حالت اشکال‌یابی؛ در شرایط پیش‌بینی‌نشده لاگ بیشتری چاپ می‌کند

-v
    نمایش نسخه + بررسی نسخه‌ی جدید
-h
    راهنما
```

> [!TIP]
> در ویندوز برای دادن پارامتر از **CMD** استفاده کنید (داخل پوشه‌ی برنامه): `cfst -tl 200 -dn 20`. در **PowerShell** به‌جای `cfst` بنویسید `.\cfst` و در لینوکس/macOS بنویسید `./cfst`.

## \# مثال‌های کاربردی

### IPv4 / IPv6 و IP دلخواه

```bash
# IPv4 (پیش‌فرض)
cfst -f ip.txt

# IPv6 (یک فایل می‌تواند هم IPv4 و هم IPv6 داشته باشد)
cfst -f ipv6.txt

# مستقیم با پارامتر
cfst -ip 1.1.1.1,2606:4700::/32
```

فرمت فایل رنج‌ها (مثلاً `1.txt`):

```text
1.1.1.1
1.1.1.200
1.0.0.1/24
2606:4700::/32
```

برای IP تکی لازم نیست `/32` بنویسید. رنج `/24` فقط یک IP تصادفی از بخش آخر انتخاب می‌کند؛ برای تست همه‌ی IPهای رنج، `-allip` را اضافه کنید.

### HTTPing

TCP کم‌مصرف‌تر است (timeout = ۱ ثانیه) و پیش‌فرض است. HTTP (timeout = ۲ ثانیه) برای بررسی دسترسی‌پذیری یک دامنه روی IP مناسب است. معمولاً تأخیر **ICMP < TCP < HTTP** است و هرچه جلوتر، به افت بسته حساس‌تر. در HTTPing فقط هدر پاسخ خوانده می‌شود، پس اندازه‌ی فایل مهم نیست (اما برای تست دانلود فایل بزرگ لازم است).

```bash
cfst -httping
cfst -httping -httping-code 200
cfst -httping -url https://cf.xiu2.xyz/url

# آدرس HTTP => پورت 80
cfst -httping -tp 80 -url http://cdn.cloudflare.steamstatic.com/steam/apps/5952/movie_max.webm
```

> [!WARNING]
> HTTPing در اصل نوعی **اسکن شبکه** است. روی سرور thread (`-n`) را کم کنید، وگرنه ممکن است سرویس‌دهنده‌ی سخت‌گیر سرویس را متوقف کند. اگر تعداد IPهای قابل‌استفاده در تست‌های بعدی کم و کمتر می‌شود و بعد از مدتی برمی‌گردد، احتمالاً محدودیت موقت فعال شده؛ `-n` را کم کنید.

### فیلتر منطقه

IPهای Cloudflare از نوع **Anycast** هستند: مقصد واقعی با منطقه، اپراتور و زمان تغییر می‌کند. پس به این قابلیت زیاد امید نبندید؛ ممکن است در رنج‌های زیادی حتی یک IP در منطقه‌ی دلخواه پیدا نشود. کد منطقه‌ی واقعی را با هدر پاسخ می‌خوانیم؛ دستی هم می‌توانید `http://CloudflareIP/cdn-cgi/trace` را باز کنید.

- Cloudflare / AWS CloudFront / Fastly: کد سه‌حرفی IATA مثل `HKG,LAX`
- CDN77 / Bunny: کد دوحرفی کشور مثل `US,CN`
- Gcore: کد دوحرفی شهر مثل `FR,AM`

```bash
# فقط در HTTPing کار می‌کند
cfst -httping -cfcolo HKG,KHH,NRT,LAX,SEA,SJC,FRA,MAD
```

> برای فیلتر مناطق AWS CloudFront باید `-url` را روی آدرسی از CloudFront بگذارید؛ گاهی HTTPing کد 403 برمی‌گرداند که باید `-httping-code 403` بگذارید.

### مسیر فایل‌ها

```bash
# فایل IPv4، بدون نمایش نتیجه، فقط خروجی فایل
cfst -f 1.txt -p 0 -dd

# بدون فایل خروجی، فقط نمایش (کوتیشن خالی لازم است)
cfst -f 2.txt -o "" -p 10 -dd

# مسیر نسبی (لینوکس)  /  (ویندوز با بک‌اسلش)
./cfst -f abc/3.txt -o abc/result.csv -dd
cfst -f abc\3.txt -o abc\result.csv -dd

# مسیر مطلق: اگر خود برنامه با مسیر مطلق اجرا شود، فایل‌ها هم باید مسیر مطلق باشند
/abc/cfst -f /abc/4.txt -o /abc/result.csv -dd
C:\abc\cfst -f C:\abc\4.txt -o C:\abc\result.csv -dd
```

### پورت و آدرس دلخواه

```bash
# پورت 80 => آدرس دانلود باید http:// باشد و به https ریدایرکت نشود
cfst -tp 80 -url http://speed.cloudflare.com/__down?bytes=99999999

# آدرس دلخواه: قابل دانلود مستقیم، حجم بیش از 200MB، روی Cloudflare CDN
cfst -url https://cf.xiu2.xyz/url
```

### شرط‌های تأخیر / افت بسته / سرعت

```bash
# تأخیر کمتر از 200ms، سپس تست دانلود
cfst -tl 200

# فقط تأخیر، بدون دانلود
cfst -tl 200 -dd

# تأخیر بین 60 و 200ms
cfst -tll 60 -tl 200

# افت بسته حداکثر 0.25 (صفر = هیچ افتی مجاز نیست)
cfst -tlr 0.25

# 10 IP با سرعت بالای 5 MB/s
cfst -sl 5 -dn 10

# ترکیب (پیشنهاد می‌شود -sl را همراه -tl بدهید)
cfst -tl 200 -sl 5.6 -dn 10
```

> **چرا `-tll` (حد پایین تأخیر)؟** کم‌ترین تأخیر و افت بسته لزوماً بیشترین سرعت نیست؛ سرعت انتقال می‌تواند محدود (مثلاً QoS) شود. بعضی اپراتورها همیشه IPهای هنگ‌کنگ با تأخیر کم ولی سرعت ناپایدار می‌گیرند؛ با `-tll` می‌توان آن‌ها را حذف کرد.

> اگر `-sl` بدهید و تعداد کافی IP پیدا نشود، تست **ادامه پیدا می‌کند**. برای جلوگیری، `-tl` هم بدهید. اگر هیچ IPی شرط سرعت را نداشت و `-debug` روشن باشد، همه‌ی نتایج نشان داده می‌شود تا بتوانید شرط را واقع‌بینانه‌تر کنید.

> رنج‌های عمومی Cloudflare شامل IP **مبدأ (origin)** هم هستند که قابل‌استفاده نیستند و سرعت دانلودشان 0.00 است. با `-sl 0.01` می‌توانید آن‌ها را حذف کنید.

خلاصه‌ی خروجی بر اساس شرط‌ها:

- هیچ شرطی ندادید: **همه‌ی نتایج** نمایش داده می‌شود.
- شرط تأخیر (`-tl` / `-tll`): فقط IPهای مطابق نمایش داده می‌شود؛ اگر هیچ‌کدام نبود، **خروجی خالی** است.
- شرط سرعت (`-sl`): بدون `-debug`، فقط IPهای مطابق (یا خالی)؛ با `-debug` اگر هیچ IPی مطابق نبود، **همه‌ی نتایج** نمایش داده می‌شود.

### خروجی‌های جدید (TXT و JSON)

```bash
# فقط 5 IP برتر در فایل TXT (هر خط یک IP) + JSON کامل، بدون نمایش روی صفحه
cfst -otxt best.txt -txtn 5 -ojson result.json -p 0

# بدون CSV، فقط TXT
cfst -o "" -otxt ips.txt
```

نمونه‌ی JSON:

```json

  {
    "ip": "104.27.200.69",
    "sent": 4,
    "received": 4,
    "loss_rate": 0,
    "delay_ms": 146.23,
    "speed_mbps": 28.64,
    "colo": "LAX"
  }
]
```

## \# توضیح صفحه‌ی تست (چرا «قابل‌استفاده» و «صف» فرق دارد؟)

```text
# XIU2/CloudflareSpeedTest vX.X.X (nesakhe-ye Finglish)

Shoro-e test-e takhir (halat: TCP, port: 443, mahdude: 40 ~ 150 ms, gom-shodan: 1.00)
321 / 321 [------------------------------------------] Ghabel-estefade: 30
Shoro-e test-e download (hadde-aghal: 1.00 MB/s, tedad: 5, saf: 10)
3 / 5 [-----------------------------------------↗--------------------]
```

- **Ghabel-estefade (قابل‌استفاده):** تعداد IPهایی که در تست تأخیر timeout نشدند؛ به شرط‌های حد بالا/پایین تأخیر و افت بسته ربطی ندارد.
- بعد از اعمال شرط‌ها، فقط بخشی از آن‌ها می‌ماند: همان‌ها **صف (saf)** تست دانلود هستند. تست دانلود تک‌رشته‌ای است و IPها یکی‌یکی «در صف» تست می‌شوند.
- در `3 / 5` عدد اول تعداد IPهایی است که شرط حداقل سرعت را داشته‌اند و عدد دوم همان `-dn` است. نوار فقط وقتی جلو می‌رود که IPی با سرعت کافی پیدا شود؛ پس اگر شرط سرعت سخت باشد ممکن است «گیر کرده» به نظر برسد — یعنی شرط شما از واقعیت بالاتر است؛ `-sl` را کم کنید.
- اگر `-dn` از طول صف بزرگ‌تر باشد، عدد دوم همان طول صف می‌شود.

## \# سرعت دانلود همه 0.00 است؟

تست دانلود در اصل مثل این است که دامنه‌ی آدرس دانلود را با IP موردنظر در Hosts بنویسید و با مرورگر باز کنید (مثل `curl --resolve`). اگر همه 0.00 شد، یعنی در حین تست خطایی رخ داده. فقط سه علت دارد: **آدرس تست مشکل دارد**، **IP مشکل دارد** یا **شبکه‌ی شما مشکل دارد**.

اول حتماً **`-debug`** را به دستور قبلی اضافه کنید تا علت دقیق چاپ شود. خطاهای رایج (متن خطا انگلیسی است):

1. `connection reset by peer` — اتصال ریست شده؛ آدرس یا IP مسدود شده، یا سرور درخواست را رد کرده.
2. `HTTP ... 403 / 404` — آدرس دانلود دسترسی را رد کرده (403) یا فایل پیدا نشده (404).
3. `context deadline exceeded (Client.Timeout ...)` — timeout؛ مشکل IP/شبکه یا `-dt` خیلی کوتاه است.
4. `tls: handshake failure` یا `failed to verify certificate` — آدرس دانلود با سرور IP همخوانی ندارد (مثلاً آدرس روی Fastly است ولی IP مال Cloudflare).
5. `certificate is valid for XXX, not YYY` — گواهی SSL آن IP برای دامنه‌ی آدرس شما نیست.
6. `certificate has expired or is not yet valid` — گواهی منقضی است (یا مثل ۴ و ۵).
7. `certificate signed by unknown authority` — گواهی‌های سیستم مشکل دارد (مثلاً در Termux).

اگر باز هم حل نشد:

- **آدرس تست:** چند آدرس دانلود دیگر امتحان کنید (ترجیحاً آدرس شخصی بسازید). اگر با بعضی جواب گرفتید، آدرس قبلی مشکل داشته است.
- **IP:** IPهای دیگری را هم امتحان کنید (بعضی IPها فقط TCP جواب می‌دهند ولی HTTP نه؛ مثل origin یا IPهای اختصاصی).
- **شبکه:** مثلاً با اینترنت موبایل (اشتراک USB) تست کنید و نتیجه را مقایسه کنید.

## \# رفع مشکلات منو

- **منو نمایش داده نمی‌شود:** احتمالاً پارامتر داده‌اید یا ورودی از pipe می‌آید. `-menu` بگذارید.
- **«File-e mahdude-haye IP peyda nashod»:** فایل `ip.txt` (یا فایل انتخابی) کنار برنامه نیست؛ از منوی [3] مسیر درست را بدهید، یا برنامه را از داخل پوشه‌ی خودش اجرا کنید.
- **ورودی نامعتبر:** منو عدد را با محدوده‌اش (مثلاً `1 ta 1000`) نشان می‌دهد و تا ورودی درست ندهید قبول نمی‌کند. Enter = مقدار فعلی.
- **ویندوز:** بعد از پایان تست برای بستن پنجره Enter بزنید.

## \# ساخت دستی (Manual build)

نسخه با `-ldflags` داخل متغیر `version` نوشته می‌شود:

```bash
go build -ldflags "-s -w -X main.version=v1.0.0"
```

ساخت برای سیستم/معماری دیگر با `GOOS` و `GOARCH`:

```bash
# لینوکس => ویندوز 32 بیتی
GOOS=windows GOARCH=386 go build -o Releases/cfst_windows_386/cfst.exe -ldflags "-s -w -X main.version=v1.0.0"
```

```bat
:: ویندوز => لینوکس 64 بیتی
SET GOOS=linux
SET GOARCH=amd64
go build -o Releases\cfst_linux_amd64\cfst -ldflags "-s -w -X main.version=v1.0.0"
```

با `go tool dist list` ترکیب‌های پشتیبانی‌شده را ببینید.

> ساختار کد: `main.go` (پارامترها و شروع برنامه)، `menu.go` (منوی صفحه‌ی اول)، پوشه‌ی `task` (تست تأخیر/دانلود/IP) و پوشه‌ی `utils` (خروجی‌ها، رنگ، نوار پیشرفت). متن‌های همه‌ی این فایل‌ها فینگلیش هستند.
